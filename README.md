# AI Agent 工程实践

两个从零手写、在自己机器上跑到能演示的 AI 应用。核心机制都是自己实现的——LLM 客户端、Function Calling 循环、工具注册表、RAG 检索链路、多任务并发编排，没有用 LangChain / LlamaIndex 这类框架包一层。

| 项目 | 一句话 | 跑起来是什么样 |
|---|---|---|
| **[claw](./claw/)** | 认知路由：先诊断"你卡在哪"，再决定"怎么教"的四层 Agent | 输入一句话，四路并行分析 → 认知侦察 → 带工具生成教学回复，过程逐步推送到前端 |
| **[vtuber](./vtuber/)** | B 站直播间的 AI 虚拟主播 | 观众发弹幕 → 过滤攒批 → LLM 决策 → 流式 TTS → 嘴型跟着字走、表情跟着情绪变，60fps |

合计约 **8,600 行 Python**，两个项目都能在本机跑通完整链路。

---

## 两个项目分别在解决什么

### Claw：把"教学决策"拆开

普通对话 Agent 假设"用户说的就是他真正的问题"。教学场景里这个假设经常是错的。

Claw 在生成之前先花一层算力做诊断：

```
用户输入
   ├─ L1 四路并行（asyncio.gather，总耗时 = 最慢一路）
   │    情绪指纹 / 断点诊断 / 优势识别 / 知识流
   ├─ L2 认知侦察：读四路结果之间的矛盾，输出教学策略
   ├─ L3 执行：ReAct 循环 + 工具调用（最多 3 轮，用完强制收尾）
   └─ L4 接入：FastAPI + WebSocket，每层出结果就推一段
```

**最能说明工程判断的一处**：L2 之所以单独成层，是因为三份分析结果会互相矛盾（情绪说急躁、断点说概念缺失、优势说前置其实已掌握），这种组合**没有任何 if-else 能穷举**。

→ [看详细说明](./claw/README.md)

### vtuber：实时场景下的一致性

直播是"话赶话"，不是聊天框。三个问题不解决项目根本跑不起来：

| 问题 | 解法 |
|---|---|
| 两个脑抢同一张嘴（卖货 vs 回应） | 队列项带来源标签，抢画面时**只丢"卖货"，保留"回应"** |
| 一句说完要等 1.78 秒才有下一句 | TTS 拆成合成 / 播放两段流水线，**空档 ≈ 0，4 句省 5.4 秒** |
| 弹幕能连上但一条不推 | 补齐设备指纹 `buvid` + 解析真实房间号，两样缺一不可 |

**最能说明工程判断的一处**：整条链路只有一个地方跨线程（60fps 渲染），其余全部塞进单个事件循环——**不引入第二种并发模型**。

→ [看详细说明](./vtuber/README.md)

## 自己写了什么（而不是调库）

| 能力 | claw | vtuber |
|---|---|---|
| **LLM 客户端** | 六级降级（500/401/429/非200/JSON解析失败/choices空）+ 发请求前 token 预检 | 关思考换首字延迟（6.0s → 0.8s）+ 单点故障隔离 |
| **Function Calling** | ReAct 循环 + 装饰器工具注册表 + 轮数熔断 | 决策层：判断"说不说、说什么、什么时候抢画面" |
| **RAG** | FAISS 检索 + chunk 切分 + 检索链路 | 字面向量 + 记忆库按人检索 |
| **并发编排** | `asyncio.gather` 四路并发 + 并发拆分三判据 | 5 个常驻 Task + 5 个有界队列（背压）+ 单事件循环 |
| **长连接** | WebSocket 逐步推送 | B 站直播协议：认证 / 协议级心跳 / 沉默看门狗 / 断线自愈 |
| **存储** | 分层轮次记录（靠数据完整性判断，不靠外部计数器） | SQLite WAL，内存 O(1)，按 uid 检索 |
| **Web** | FastAPI 7 REST + WS | FastAPI 13 端点 + 网页控制台 |

## 环境

两个项目独立，互不依赖，各自有 README 说明依赖与启动方式。

- Python 3.10+
- 需要配置自己的 API Key（`.env.example` 是模板，真实密钥不入库）
- claw 需要 `faiss` / `sentence-transformers`（首次运行会下载 embedding 模型）
- vtuber 需要 Windows 桌面环境（Live2D 渲染开窗口）

## 说明

- 两个项目都是个人项目，没有生产环境流量，指标都是本机实测
- 没有单元测试覆盖，验证方式是手工跑完整链路（已知的最大工程缺口）
- 代码里的中文注释、日志、终端输出保留了原样——这是开发过程的真实形态
