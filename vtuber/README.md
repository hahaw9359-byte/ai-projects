# AI 虚拟主播

B 站直播间里一个能自己接话的虚拟主播：**听弹幕 → 决定说不说 → 开口 → 嘴型跟着字走、表情跟着情绪变**。

Python 单机跑通全链路，不依赖任何云直播平台：

```
弹幕长连接 → 过滤/攒批 → LLM 决策 → 流式 TTS → 字级时间戳 → 60fps Live2D
```

约 5,500 行 Python，其中约 1,100 行是厂商协议包（火山 SDK 559 行 + B 站直播协议 560 行），业务自研约 4,400 行。

---

## 为什么这个项目不简单

直播是"话赶话"的实时场景，不是聊天框。三个问题不解决，东西根本跑不起来：

| 问题 | 表面现象 | 真正的原因 | 解法 |
|---|---|---|---|
| **两个脑抢同一张嘴** | 卖货讲到一半被打断，或者弹幕回应听不到 | 行为脑（卖货）和大脑（回应）共用一个 TTS 队列，谁都可以塞；抢画面时如果不清队列，旧话会在新话题后面播 10 秒；如果全清，弹幕回应也被一起清掉 | 队列项**带来源标签**，抢画面时只清 `"卖货"`、保留 `"回应"`——填充可以过时，对话不行 |
| **说话有断档** | 一句说完要等 1.78 秒才开口说下一句，听着像掉线 | 合成和播放串行：播完 → 才去合成 → 合成完 → 才播 | TTS 拆成**合成工人 + 播放工人**两段流水线，用一个 `Queue(maxsize=2)` 做缓冲，边播边合成 |
| **弹幕能连上，但一条都不推** | WebSocket 连上了，榜单、进房提示全都有，就是没有弹幕 | B 站只给带**设备指纹**的连接推弹幕类广播；而且只认**真实房间号**（短号不行） | 连接前先拿 `buvid3`、再用 `room_init` 解析真实房间号，两样少一样都不行 |

## 架构

### 线程模型：只有一个地方跨线程

```
主线程    stage/render.py     开窗 + 60fps 渲染循环，只读"黑板"快照，从不等任何人
          ↑ 读快照                    ↓ 写当前模型
子线程    webapp.py（uvicorn）  小脑 + 大脑 + 行为脑 + TTS + HTTP 端点，同一个事件循环
```

Live2D 必须在主线程以固定帧率跑，所以渲染独占主线程。其余全部在子线程的**单个事件循环**里——**不引入第二种并发模型**。跨线程不传对象，只传快照。

### 五个脑，靠队列串起来

```
弹幕源 ──→ raw_q ──→ 过滤链 ──→ 攒批窗口 ──→ audit_q ──→ LLM 审核 ──→ brain_q
(长连接)   (200)    (5 个过滤器)   (2条/2秒)      (50)                    (100)
                                                                          ↓
                                          行为脑（卖货）──┐
                                                         ├──→ TTS 队列 ──→ 合成 ──→ 播放
                                          大脑（回应）────┘
                                                         ↓
                                                    黑板（嘴型/情绪）──→ 渲染线程
```

每个队列都有明确容量，**写满就是背压**——不会无限堆内存。5 个常驻 Task 挂在同一个事件循环上，任何一个环节挂掉都不会拖垮其它环节。

## 五个关键实现

### 1. 队列分级：填充可以丢，对话不能丢

队列项是 `(来源, 文本)`，来源只有两个值：

| 来源 | 抢画面时 | 理由 |
|---|---|---|
| `"卖货"` | **清掉** | 它是填充内容，话题已经过去了，说出来反而奇怪 |
| `"回应"` | **保留** | 观众问的话必须回，丢一条就是一次事故 |

这两条规则都是实测踩出来的，不是设计出来的。第一版两个都清 → 大脑的回应一句都听不到；第二版两个都不清 → 抢了画面十几秒谁都没说话（队列里排着两句卖货，一句要播 5~6 秒）。

### 2. 说完一句不等人：TTS 拆两段

```
串行：合成(1.78s) → 播放(5.42s) → 合成(1.78s) → 播放(5.42s)      句间空档 1.78s
流水：合成 ─┐
             └→ 播放(边播边合成下一句)                              句间空档 ≈ 0
```

4 句话累计省下 **5.4 秒**。这是纯播放速度带来的体验差异，语音内容一个字都没变。

### 3. 嘴型不是估的，是算的

TTS 返回**字级时间戳**，所以嘴型有精确的时间轴，不是"放音时随机张嘴"：

```
字级时间戳 → 音素 → 嘴型（三跳翻译）
渲染时按当前时间 t 在相邻两帧之间插值
```

声音、嘴型、表情三样东西来自**同一个时间轴**，所以天然同步。

### 4. 记忆从"全量读进内存"换成 SQLite

旧版启动时把整个日志读进 `dict[昵称, 50 条]`——**人数 × 50 条全部常驻，人数还没上限**，跑久了吃光机器，而且每人只记得最后 50 句。

现在：弹幕收到即 `INSERT`，投递前按人查 `ORDER BY id DESC LIMIT 12`。**内存 O(1)，且不截断历史**（要限制就用按时间清理 90 天，而不是砍条数）。

两个 SQLite 配置是关键：

```python
PRAGMA journal_mode=WAL     # 写只追加日志、不锁读者
PRAGMA synchronous=NORMAL   # 不必每次提交都 fsync
```

不这么设，每条弹幕一次 `commit` 都要 fsync，磁盘一忙就是几十毫秒——而这行代码跑在**事件循环**里，几十毫秒里 TTS、收包、大脑全部停摆。

**按 `uid` 查，不按昵称**：两个人重名会串台，观众改昵称历史就断。

### 5. 长连接的保活方式得自己管

库自带的 WebSocket 心跳**不能开**——B 站弹幕服务器不回 pong，库等不到就误判连接已死，实测**约 40 秒断一次**（表现是"弹幕时有时无")。

改成两样：**协议级心跳**（op=2，每 30 秒）+ **沉默看门狗**（90 秒没数据才重连）。改完实测 **110 秒稳定不掉线**。

## 实测数据

| 指标 | 结果 | 对照 |
|---|---|---|
| 首字延迟 | **0.8s** | 开 `thinking` 时 6.0s，且正文常被思考吃光 |
| 句间空档 | **≈ 0** | 原 1.78s，4 句省 5.4s |
| 弹幕连接稳定性 | **110s 不掉线** | 原约 40s 断一次 |
| 记忆内存 | **O(1)** | 原随人数 × 条数线性增长 |
| 连发 10 条弹幕 | 10 条全通过 → 5 批 → 回 5 句 | 调优前只回 2 句 |
| 渲染帧率 | **60fps** | 渲染线程独立，不受业务阻塞 |
| 单点故障 | LLM 抽风跳过这一批、TTS 抽风跳过这一句 | 原来一抽风 = 弹幕从此全部没人回 |

## 运行

```bash
cd vtuber
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy .env.example .env        # 填入密钥
```

`.env` 只有两项：

| 变量 | 用途 |
|---|---|
| `Deepseek_key` | 大模型（决策 + 生成） |
| `VOLC_API_KEY` | 火山语音合成 |
| `BILI_ROOM_ID` | B 站房间号，留空 = 安静模式（只卖货，不接弹幕） |

```bash
.venv\Scripts\python.exe run_vtuber.py        # 完整形态：窗口 + 出声 + 控制台
.venv\Scripts\python.exe run_all.py 30        # 只跑逻辑，不开窗不出声（验证数据流用）
```

跑起来之后：

| 地址 | 是什么 |
|---|---|
| `http://127.0.0.1:8000` | 控制台页面：状态 / 暂停继续 / 说一句 / 切换才艺 / 换模型 / 换文案 / 弹幕连接 / 用量 |
| `http://127.0.0.1:8000/docs` | FastAPI 自动生成的接口文档，13 个端点可直接调 |

**切换形象**：模型文件夹放进 `stage/Resources/v3/` → 控制台点一下 → 渲染线程下一帧自己加载。
**切换话术**：`.txt` 放进 `卖货文档/` → 控制台点一下 → 下一轮就讲新内容（重启后记住上次选的）。

## 技术栈

`Python` · `asyncio`（5 常驻 Task + 队列背压） · `FastAPI` / `WebSocket` / `uvicorn` · `SQLite`（WAL） · `DeepSeek API`（流式） · `火山 TTS`（字级时间戳） · `Live2D Cubism SDK` · `B 站直播协议`（WebSocket + protobuf）

## 目录

```
vtuber/
├── core/              shared 地基：数据契约 / 共享快照 / 记忆库
├── cerebellum/        小脑：采集 / 五态过滤 / 攒批 / LLM 审核（5 个 Task）
├── cerebrum/          大脑：抢画面 → 流式生成 → 释放
├── performance/       行为脑：状态机 + 可切换 Skill（卖货）
├── voice/             声音层：TTS 合成播放 / 字级时间戳→嘴型 / 情绪→表情 / 黑板
├── stage/             舞台：主线程渲染 + Live2D 模型
├── pipeline.py        流水线装配
├── webapp.py          FastAPI 接入层（13 端点 + WebSocket）
├── webui.html         网页控制台（单页，零依赖）
└── run_vtuber.py      总入口：主线程渲染 + 子线程五脑
```
